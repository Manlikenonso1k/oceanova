Role: Senior Laravel & Filament 3 Architect.
Task: Resolve "Vanishing Stock" logic in a Departmental Inventory System.

The Problem: When a stock request is approved, the inventory is not incrementing correctly, or the Daily Stock record is overwriting the master inventory with zero.

1. The "Source of Truth" Rule:

The Products (or Ingredients) table is the Master Source of Truth.

The DailyStock table is just a Log.

2. Fix the Approval Action (StockRequestResource):

In the "Approve" Action, use the increment() method specifically.

Code Logic: $product = Product::find($record->product_id); $product->increment('current_stock', $record->quantity);

Crucial: Do NOT manually set $product->current_stock = $new_val. Using increment() prevents "race conditions" where two people saving at once causes a 0.

3. Fix the Daily Stock Flow (DailyStockResource):

Opening Stock: When a Barman/Chef creates a new Daily Stock record, the opening_stock field must default to the current_stock value from the Products table.

Added Stock: This field should automatically pull any "Approved" requests for that item that happened since the last daily report.

The Update Logic: Only when a Daily Stock record is saved, should it update the Master Product table.

Formula: Product::where('id', $product_id)->update(['current_stock' => $closing_stock]);

4. Testing/Admin Permissions:

Ensure the DeleteAction is only visible if auth()->user()->hasRole('admin'). This allows me to wipe the "0" values while I'm fixing the logic.

5. Prevent Null Errors:

In the Migration and Models, ensure opening, added, closing, and sales all have a default(0). If a field is empty, the math must treat it as 0, not null.

Instructions: Rewrite the Approve action in StockRequestResource and the afterCreate hook in DailyStockResource to follow this logic exactly.
